# OWASP Top 10 for Agentic Applications: Themis control mapping

Source: OWASP GenAI Security Project, "OWASP Top 10 for Agentic Applications" (published 2025-12-09), https://genai.owasp.org/2025/12/09/owasp-top-10-for-agentic-applications-the-benchmark-for-agentic-security-in-the-age-of-autonomous-ai/ (IDs ASI01 to ASI10 and titles read from the live page, retrieved 2026-10-11).

This is an informational design mapping, not a certification. The ASI list is a different list from the LLM Top 10 in [owasp-llm.md](owasp-llm.md); the IDs are not interchangeable and the two tables are kept apart on purpose. The OWASP page titles ASI02 "Tool Misuse" and ASI04 "Agentic Supply Chain Vulnerabilities"; those titles are used as published. Only the ten IDs and titles were taken from OWASP. The descriptions in the "Themis control" column are about Themis code, not about OWASP's text.

Paths are relative to `packages/` unless they start with `apps/`.

| ID | Risk | Themis control | Code path (file:symbol) | Test | Residual / gap |
|---|---|---|---|---|---|
| ASI01 | Agent Goal Hijack | The step order is a fixed workflow, not model chosen. External tool output is redacted and wrapped as untrusted data. Write and execute calls need a human decision whatever the model was told | `themis-core/src/workflow.ts:THEMIS_WORKFLOW`, `themis-core/src/workflow.ts:advance`, `themis-gateway/src/gateway.ts:wrapUntrusted` | `themis-core/test/workflow.test.ts` ("rejects out-of-order steps without changing the run"), `packages/themis-gateway/test/wrapper-breakout.test.ts` ("a closing tag inside tool output cannot end the wrapper early") | Wrapper tags inside tool output are neutralised by `neutraliseWrapperTags`. GAP: tool descriptions from connected servers are not wrapped. A hijacked model can still produce misleading findings; the human approval gate limits actions, not text. |
| ASI02 | Tool Misuse | Default-deny allowlist per skill, deterministic read/write/execute classification, write and execute only as propose-then-approve, per-server call budget | `themis-core/src/mcp/config.ts:serversForSkill`, `themis-core/src/mcp/tool-policy.ts:classifyTool`, `themis-core/src/mcp/tool-policy.ts:dispositionFor`, `themis-gateway/src/gateway.ts:createGateway` | `themis-core/test/mcp/governance.test.ts` ("returns nothing for a skill no server lists (default-deny)"), `themis-gateway/test/gateway.test.ts` ("turns write/execute calls into pending approval requests — never executed", "denies unknown tools", "enforces the per-server call budget") | A read-classified tool on a connected server can still return harmful data. Tools you connect directly to your assistant in plugin mode bypass Themis. |
| ASI03 | Identity & Privilege Abuse | A model cannot approve its own actions: only a human decision marks an approval `decidedBy: human`. The dashboard needs a per-launch session token and same-origin checks. Secrets are redacted from everything logged | `themis-core/src/approvals.ts:canExecuteApproval`, `themis-app/src/server/security.ts:checkSession`, `themis-app/src/server/security.ts:checkOrigin`, `themis-plugin/src/approval.ts:decideFromHuman` | `themis-gateway/test/approval-invariant.test.ts` ("refuses an \"approved\" record that no human decided (tampered store)"), `themis-app/__tests__/server/security.test.ts` ("checkSession needs the cookie for this port", "checkOrigin protects state-changing requests") | GAP: Themis does not issue, rotate or scope identities for the external servers it calls; credentials for those servers are yours to scope. The dashboard session token protects one local launch; it is not user authentication. |
| ASI04 | Agentic Supply Chain Vulnerabilities | Servers are opt-in per skill; unreachable servers degrade to no tools; package dependencies are allowlisted per package; skill content is reviewed text under version control | `themis-core/src/mcp/config.ts:loadMcpServers`, `themis-gateway/src/gateway.ts:createGateway`, `scripts/check-deps-themis.js` (`RULES`) | `themis-core/test/mcp/governance.test.ts` ("drops entries with invalid id, transport or url"), `themis-gateway/test/gateway.test.ts` ("soft-fails: unreachable servers mean no tools; a throwing call is an error result") | GAP: tool descriptions from a connected server pass to the model unmodified, so a malicious server can try to steer the model through them. GAP: intel content in the skills is committed from the maintainer's machine, so the maintainer is a trust assumption. Release provenance is Phase 7 work and is not claimed here. |
| ASI05 | Unexpected Code Execution | Themis does not execute model output. Task input is sanitised. Write and execute tools run only after human approval, with the original arguments, once | `themis-core/src/sanitise.ts:sanitiseTask`, `themis-gateway/src/gateway.ts:createGateway` (`executeApproved`) | `themis-core/test/sanitise.test.ts` ("throws ValidationError if javascript: present (lowercase)"), `themis-gateway/test/approval-invariant.test.ts` ("executes a human-approved request exactly once, with the original arguments", "after a restart, redacted arguments are never executed; clean ones are") | An approved execute tool runs on the external server with that server's own privileges; Themis cannot sandbox it. |
| ASI06 | Memory & Context Poisoning | Run context is validated and size-limited. Findings that contain secrets are force-BLOCKed before a model sees them, and BLOCKed results are left out of the report | `themis-core/src/sanitise.ts:validateContext`, `themis-core/src/guardrail.ts:precheckSecrets`, `themis-core/src/guardrail.ts:synthesisableResults` | `themis-core/test/sanitise.test.ts` ("throws ValidationError if slug has uppercase chars"), `themis-core/test/guardrail.test.ts` ("synthesis excludes BLOCKed results") | GAP: there is no detection of subtly false content in earlier findings that later steps then build on. The guardrail verdict is model produced. |
| ASI07 | Insecure Inter-Agent Communication | There is no free-form agent-to-agent channel. Sub-task results enter through the fixed workflow, which rejects results for sub-tasks that are not ready, redacts findings and ignores model-supplied verdicts | `themis-core/src/workflow.ts:advance`, `themis-core/src/schedule.ts:readySubTasks`, `themis-plugin/src/step-io.ts` | `themis-core/test/workflow.test.ts` ("fanout rejects results for sub-tasks that are not ready, leaving the run retryable", "fanout redacts findings and ignores model-supplied verdicts"), `themis-plugin/test/step-io.test.ts` | GAP: sub-agent messages in plugin mode are not signed or authenticated; they rely on the host AI client. |
| ASI08 | Cascading Failures | Dependency-staged scheduling, a plan cap of `MAX_SUBTASKS`, cycle breaking in the planner, fail-closed guardrail defaults, and BLOCKed results excluded from the report | `themis-core/src/schedule.ts:scheduleStage`, `themis-core/src/planning.ts:normaliseSubTasks`, `themis-core/src/guardrail.ts:guardrailFailure` | `themis-core/test/schedule.test.ts` ("dispatches only sub-tasks whose dependencies are complete"), `themis-core/test/planning.test.ts` ("breaks a dependency cycle so the plan can always make progress"), `themis-core/test/guardrail.test.ts` ("guardrailFailure blocks") | Honest note: `scheduleStage` releases every pending task when nothing is ready, so a malformed plan cannot stall the run. A task whose dependency never completed can therefore still be dispatched. |
| ASI09 | Human-Agent Trust Exploitation | The approval record shows the tool, the class and redacted arguments; the model's stated reason is secret-redacted and capped at 1000 characters; the decision is recorded as human and audited | `themis-core/src/approvals.ts:newApprovalRequest` (`MAX_APPROVAL_REASON_CHARS`), `themis-app/src/server/routes/approvals.ts:approvalView`, `themis-plugin/src/tools/gateway-tools.ts` (elicitation prompt) | `themis-core/test/approvals.test.ts` ("caps the reason length"), `themis-app/__tests__/server/approvals.test.ts` ("lists approval views with redaction and in-memory flags") | GAP: the reason text is written by the model and can be persuasive or wrong. A reviewer must judge the arguments, not the explanation. |
| ASI10 | Rogue Agents | There is no long-lived autonomous agent process. Each run is a bounded workflow with call budgets, every step and tool call is written to an append-only audit log, and a failed audit write fails the call | `themis-core/src/audit-log.ts:auditEvent`, `themis-core/src/store/sqlite.ts` (append-only `audit_events`), `themis-gateway/src/gateway.ts:createGateway` | `themis-core/test/store.test.ts` ("makes audit_events append-only at the database level"), `themis-gateway/test/gateway.test.ts` ("fails closed when the audit log cannot be written") | GAP: no runtime anomaly detection and no remote kill switch beyond stopping the run or closing the gateway. The audit log is local and tamper-resistant at the database level, not tamper-proof against someone with file access. |
