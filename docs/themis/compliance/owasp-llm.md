# OWASP Top 10 for LLM Applications: Themis control mapping

Source: OWASP Top 10 for LLM Applications, 2025 edition, https://genai.owasp.org/llm-top-10/ (IDs and titles read from the live page, retrieved 2026-10-11).

This is an informational design mapping, not a certification or an attestation. Every row names a real file and symbol, and the test that exercises it. Where Themis has no control, the row is marked `GAP`. This list is separate from the agentic threat list in [owasp-agentic.md](owasp-agentic.md); the two use different IDs and must not be merged.

Paths are relative to `packages/` unless they start with `apps/`. "Hosted MCP" means the read-only Aegis endpoint at `apps/web/app/api/mcp/route.ts`, which serves public skill text and runs no model.

| ID | Risk | Themis control | Code path (file:symbol) | Test | Residual / gap |
|---|---|---|---|---|---|
| LLM01 | Prompt Injection (including via tool output) | External tool output is redacted, cut at 4000 characters and wrapped as untrusted data before it reaches the model; closing-tag sequences inside tool output are neutralised before wrapping | `themis-gateway/src/gateway.ts:wrapUntrusted`, `themis-core/src/secrets.ts:redactSecrets` | `packages/themis-gateway/test/wrapper-breakout.test.ts` (5 tests: closing tag, case and spacing variants, truncation boundary, attribute injection, ordinary output unchanged) | `neutraliseWrapperTags` escapes any opening or closing wrapper tag before wrapping. Tool descriptions from connected servers are not wrapped (GAP, see the README open gaps). Existing coverage of wrapping and redaction: `themis-gateway/test/gateway.test.ts` ("runs read tools and wraps output as untrusted", "redacts and truncates read output"). Wrapping reduces the risk, it does not guarantee a model ignores instructions in tool output. |
| LLM02 | Sensitive Information Disclosure | Secret and email redaction on tool arguments, tool results, approvals, audit data, findings and reports | `themis-core/src/secrets.ts:redactSecrets`, `themis-core/src/redact.ts:redactDeep`, `themis-core/src/approvals.ts:newApprovalRequest` | `themis-core/test/secrets.test.ts` (13 cases, e.g. "redacts multiple secrets in same string"), `themis-core/test/redact.test.ts` ("redacts values under sensitive keys"), `themis-gateway/test/gateway.test.ts` ("audits every call and result with redacted data") | Redaction is pattern based and cannot catch every secret format. In standalone mode, task text and sub-task context go to the model provider you choose. The `.env` key file is mode 0600 on macOS and Linux only. |
| LLM03 | Supply Chain | The deterministic engine has no model or network dependencies, and dependency allowlists are enforced per package | `scripts/check-deps-themis.js` (`RULES`), `scripts/check-deps.js` | `scripts/tests/check-deps.test.js`; `npm run check:deps` (a local script; a CI workflow for it is Phase 7 work) | GAP: npm provenance and release pinning are Phase 7 work and are not claimed here. Intel content in the skills is committed from the maintainer's machine, so the maintainer is a trust assumption. Tool descriptions from connected MCP servers reach the model unmodified; connect only servers you trust. |
| LLM04 | Data and Model Poisoning | Not applicable to Themis itself: it does not train, fine-tune or host a model. Skill and intel content is reviewed text under version control | `packages/aegis/skills/` (committed content), `scripts/lint-skills.js` | `scripts/tests/lint-skills.test.js` | GAP: poisoned upstream intel committed by the maintainer would not be detected by code. Provider-side model poisoning is outside Themis. |
| LLM05 | Improper Output Handling | Task input is sanitised and size-limited; tool output is only surfaced as data and never executed; model-supplied guardrail verdicts are parsed fail-closed | `themis-core/src/sanitise.ts:sanitiseTask`, `themis-core/src/sanitise.ts:validateContext`, `themis-core/src/guardrail.ts:parseGuardrailVerdict` | `themis-core/test/sanitise.test.ts` ("throws ValidationError if <script present (lowercase)"), `themis-core/test/guardrail.test.ts` ("defaults to BLOCK on unparseable or unknown verdicts") | The sanitiser is a deny-list for obvious script and encoded payloads, not a full content filter. Reports are text; what a downstream consumer does with them is outside Themis. |
| LLM06 | Excessive Agency (human approval) | Write and execute tools are propose-only. A pending approval runs only after a human decision, once. Model output can never approve | `themis-core/src/approvals.ts:canExecuteApproval`, `themis-core/src/store/sqlite.ts:decideApproval`, `themis-plugin/src/approval.ts:decideFromHuman`, `themis-app/src/server/routes/approvals.ts:registerApprovalRoutes` | `themis-gateway/test/approval-invariant.test.ts` ("refuses an \"approved\" record that no human decided (tampered store)", "executes a human-approved request exactly once, with the original arguments"), `themis-plugin/test/approval-invariant.test.ts` ("model-supplied arguments cannot approve: no tool takes an approval decision"), `themis-app/__tests__/server/approvals.test.ts` ("static invariant: only routes/approvals.ts calls decideApproval, exactly once") | The invariant protects against model-driven approval, not against a user who approves without reading. In plugin mode, tools you connect directly to your assistant bypass Themis. |
| LLM06 | Excessive Agency (tool scope) | Per-skill tool allowlist, default-deny. Write and execute exposure is gated by the server's `allowWrite` opt-in. Tool class comes from a deterministic classifier, not the model | `themis-core/src/mcp/config.ts:loadMcpServers`, `themis-core/src/mcp/config.ts:serversForSkill`, `themis-core/src/mcp/tool-policy.ts:classifyTool`, `themis-core/src/mcp/tool-policy.ts:dispositionFor` | `themis-core/test/mcp/governance.test.ts` ("returns nothing for a skill no server lists (default-deny)", "defaults to write when there is no positive read-only signal", "a server only permits write/execute surfacing when it opted in") | Classification is heuristic and conservative: unknown tools default to write, which can over-block a harmless tool. |
| LLM07 | System Prompt Leakage | Not a secret-bearing design: prompts are open source text in the repository and carry no credentials. Secrets are never placed in prompts, and redaction applies to anything that flows through the gateway | `themis-core/src/prompts/`, `themis-core/src/secrets.ts:redactSecrets` | `themis-core/test/prompts-orchestration.test.ts`, `themis-app/__tests__/prompt-parity.test.ts` | Not applicable as a confidentiality risk because the prompts are public. GAP: no control prevents a model from echoing its prompt. |
| LLM08 | Vector and Embedding Weaknesses | Not applicable: Themis has no vector store, embedding pipeline or retrieval index | none | none | GAP by design: nothing to defend. If retrieval is added later, this row must be revisited. |
| LLM09 | Misinformation | Findings pass a guardrail stage that can BLOCK or FLAG them, and a BLOCKed result is excluded from synthesis. Secrets in a finding force BLOCK before any model sees it | `themis-core/src/guardrail.ts:precheckSecrets`, `themis-core/src/guardrail.ts:synthesisableResults`, `themis-core/src/workflow.ts:advance` | `themis-core/test/guardrail.test.ts` ("synthesis excludes BLOCKed results", "precheck passes clean findings to the model (null) and force-BLOCKs secrets"), `themis-core/test/workflow.test.ts` ("guardrail requires a verdict for every result and fails closed on unknown verdicts") | The verdict itself comes from a model, so the guardrail can be wrong. Themis does not fact-check findings; a human must review reports before acting on them. |
| LLM10 | Unbounded Consumption | Per-server call budget (hard-capped), per-call timeout (hard-capped), 4000-character output cap, plan capped at `MAX_SUBTASKS` (8), 64 KB request body cap on the dashboard and the hosted MCP route, 20000-character phase cap on the hosted MCP | `themis-gateway/src/gateway.ts:createGateway` (budget), `themis-core/src/mcp/config.ts:loadMcpServers` (clamped `maxCalls`, `timeoutMs`), `themis-core/src/planning.ts:MAX_SUBTASKS`, `apps/web/app/api/mcp/route.ts:MAX_BODY_BYTES`, `packages/aegis/mcp/server.js:MAX_PHASE_CHARS` | `themis-gateway/test/gateway.test.ts` ("enforces the per-server call budget"), `themis-core/test/mcp/governance.test.ts` ("parses a valid http server and clamps limits"), `themis-core/test/planning.test.ts` ("caps the plan at MAX_SUBTASKS") | GAP: the hosted MCP route has no per-client rate limit today. A best-effort in-memory limiter is planned in Phase 6 Task 6.2; on serverless hosting each instance keeps its own memory, so it limits abuse but is not a hard quota. Model token spend in standalone mode is governed by your provider account, not by Themis. |
