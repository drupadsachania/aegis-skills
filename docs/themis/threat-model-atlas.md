# Threat model (MITRE ATLAS)

This is Themis's own threat model, written with MITRE ATLAS. It lists what Themis protects, where trust changes, which ATLAS techniques apply, what the code does about each one, and what remains open. It is informational and is not a certification. The OWASP and NIST mappings in [the compliance set](./compliance/README.md) are the design mappings shown to reviewers; this page is the threat model they sit next to.

Source and version: ATLAS data version 2026.09 (modified 2026-09-15), read from MITRE's official data repository at https://github.com/mitre-atlas/atlas-data (file `dist/v6/ATLAS-2026.09.yaml`, tag v2026.09), retrieved 2026-10-11. This is the same version that the Aegis `mitre-atlas` skill was corrected against and that `scripts/check-atlas-ids.js` checks. The https://atlas.mitre.org site was also reached on 2026-10-11, but its pages did not return a readable technique list, so the repository data is the source of every ID and name below. Tactic names are the 2026.09 names: Reconnaissance (AML.TA0002), Resource Development (AML.TA0003), Initial Access (AML.TA0004), AI Model Access (AML.TA0000), Execution (AML.TA0005), Persistence (AML.TA0006), Privilege Escalation (AML.TA0012), Defense Evasion (AML.TA0007), Credential Access (AML.TA0013), Discovery (AML.TA0008), Lateral Movement (AML.TA0015), Collection (AML.TA0009), AI Attack Adaptation (AML.TA0001), Command and Control (AML.TA0014), Exfiltration (AML.TA0010), Impact (AML.TA0011).

## Assets

| Asset | Why it matters |
|---|---|
| Approval decisions | They are the only gate between a model's proposal and any external tool call (read, write or execute) |
| The audit log and run state in `~/.themis/themis.db` | Evidence of what the agent did |
| Credentials and tokens for external MCP servers, and secrets in task text | Disclosure would give an attacker access elsewhere |
| Reports and findings | Users act on them |
| Skill content (Aegis) | It shapes what a model is told to do |

## Trust boundaries

1. **Host AI client and the Themis plugin (Mode 1).** The model on the host is untrusted for decisions: it can propose and cannot approve. The host's elicitation prompt, answered by a person, is the approval channel.
2. **Dashboard and browser (Mode 2).** The dashboard listens on 127.0.0.1, needs a per-launch session token, checks Host and Origin, and sends a strict Content-Security-Policy and no CORS headers.
3. **Gateway and external MCP servers.** Everything an external server returns is untrusted data. Servers are reachable only by the skills that list them, and write or execute tools appear only if the server opted in.
4. **Aegis content supply chain.** Skill methodology is written text under version control. Intel blocks are committed from the maintainer's machine, so the maintainer's workstation and the feeds it reads are inside the trust boundary. Content is updated monthly.
5. **Hosted Aegis MCP.** A stateless, read-only endpoint that serves public skill text. It has no model call, no database and no credentials.

"Tactic" shows an ATLAS tactic only where a published ATLAS case study in the 2026.09 data pairs that technique with that tactic. Where the data does not pair them, the cell says so rather than guessing.

## ATLAS techniques not addressed

Themis does not train, host or fine-tune a model, so training-time techniques such as AML.T0020 Training Data Poisoning and AML.T0018 Manipulate AI Model apply to the model provider, not to Themis. It has no retrieval index, so RAG-specific techniques do not apply either. If retrieval or persistent agent memory is added, this page must be revisited.
